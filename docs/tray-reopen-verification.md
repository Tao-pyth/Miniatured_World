# v0.9.9 トレイからの再表示

ウィンドウを閉じた後、トレイの「ウィンドウを表示」「設定」「発見」またはアイコンから再表示すると、同じWorldセッションの時間進行が戻る。一時停止していた場合は停止状態を保ち、「再開」で進められる。活動取得OFFやラボ非表示も維持する。

ウィンドウを閉じていた時間をまとめて進めることはしない。「隠す」では従来どおり非表示中もWorldが進む。「終了」で終えたセッションは再表示しても復活しない。

`--stability-log` による診断中にウィンドウを閉じると、その診断ログは従来どおり `cancelled` で中止する。再表示でログを再開しない。新しい完全な診断結果が必要な場合は新規に起動する。時間指定の自動終了条件は既存動作を継承する。

## 自動検証

全160テスト合格（既存148＋追加12）。追加ケースは、閉じる/再表示の繰り返し、同じセッションと設定の保持、手動一時停止と再開、活動OFF、ラボ非表示、トレイ4入口、終了/時間指定完了後の非再開、診断ログの中止、hide/show時のタイマー維持を実イベントループで確認する。

## Windows実機確認

Windows 11 Pro 10.0.26200、Python 3.13.7、Qt 6.9.3。実際のWindowsウィンドウと実活動Providerを使用。クリック透過は専用の別プロセス受信面へWindows入力を送り、ONで受信、OFFでラボを操作できることを確認する。

修正前に失敗したWM_CLOSE→トレイ再表示を含む20項目すべてが合格した。トレイはアプリが生成した実QActionから呼び出し、人によるタスクバーアイコン操作とは区別する。100%/150%の3画面間移動も確認した。

## 配布確認

既存のPySide6 6.9系とPyInstallerで単体exeを作り、exe内の41モジュールの実行コードと184素材、wheel内の226ファイルがソースと一致することを確認した。GUI一時実行15秒、Windows実活動GUI30秒、CLI5フレームも正常完了した。検証時は `MINIATURED_WORLD_DATA_DIR` を専用先へ設定し、一時実行または検査用設定だけを使った。通常の保存データは検査に使っていない。

公開後にはexeとSHA256を取得し直し、一致と起動・再表示を再検証する。公開物の検証結果とハッシュはOODAのAct記録へ残す。

作成したexeでも、閉じる→トレイ通知による再表示を2回実行し、画面の実験時間が1.4→2.7、2.7→3.9と進んだ。アプリ自身のWindowsウィンドウへWM_CLOSEを送り、[Qt 6.9の公式実装](https://github.com/qt/qtbase/blob/6.9/src/plugins/platforms/windows/qwindowssystemtrayicon.cpp)に基づくトレイ選択通知から復帰させた。値は対象アプリのUI Automationから読み取った。人によるタスクバーアイコンのクリック、画面キャプチャ、他アプリの内容取得は行っていない。

詳細証拠はOODA v0.9.8 Act loop 002と `logs/tray-reopen-v0.9.9` に記録する。

## 残件

ロック中のWorld停止、8時間連続稼働、描画FPS、125%/200%倍率、入力欠落率の保証は本修正に含めない。今回の短時間検証をV1全体の合格や長時間試験の代替としない。
