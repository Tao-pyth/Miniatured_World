# ADR 0014: 問題ファイル単位で保存を休止する

日付: 2026-09-12。状態: 採用。対象: v0.9.12。

保存データが不正なJSON・文字コード・構造の場合、起動前に例外が伝播していた。未知のスキーマや項目を既知の設定として読み込むと、次の保存で未知項目を消してしまう経路もあった。初期値への置換だけでは原本を守れない。

本人が「壊れたファイルは保護して保存を止め、正常な設定・発見は保存し続ける」方針を承認したため、JsonStoreで読込検証とファイル単位の書込み許可を管理する。問題ファイルは原位置に保持し、読み込み不能または未対応という固定の理由だけを持つ。保存前にまだ評価されていない既存ファイルも検証し、直接saveからの上書きを防ぐ。

JSON構文・文字コード・重複項目・型・数値範囲・非有限数・スキーマ・未知項目を検証する。スキーマ1の省略可能な項目は既存の初期値で補う。説明状態の未知の文字列は従来どおり未説明として扱う。不正な設定から活動取得の許可を推定せず、一時設定の活動取得はOFFにする。GUIの既存の取得選択を再利用する。

正常な設定や発見は通常どおり利用・保存する。発見の原本が保護されている場合、新しい発見はメモリ内に保持する。一度保護したファイルは同じStoreの生存中に自動解除せず、修復・復元後の再起動で再評価する。これは一時設定を原本へ無断で昇格させないためである。

画面の非モーダル説明とCLIの通知には、保存されないデータ種別と再起動時の再確認だけを表示する。ファイル本文、任意のキー名、OS例外の詳細は表示・ログへ含めない。

自動初期化・退避コピー・削除・形式移行は行わない。初期化や削除のUIは別のデータ管理作業に属し、実行前確認という既存仕様を維持する。実行中の外部編集の競合解消と、通常書込み障害の再試行も別件とする。
