# ADR 0018: 明示的な設定・発見削除と再保存の境界

状態: 採用。OODA baseline v0.9.15 / Decide001、対象v0.9.16。

ファイルや一覧だけを消すと、Storeのpending、Managerの累積集合、Worldの当回発見が次tickや終了時に旧内容を復活させる。通常の保存回復と削除は異なる利用者の意図なので、対象別に保存停止を記録する。

確認後にStoreの旧pendingを破棄し、既知の正本名だけを書込み抑止する。一時ファイルの所有範囲を検査してからunlinkする。予約名の古い一時ファイルも対象とし、再帰操作を行わない。失敗しても旧pendingを再保存せず、原本の読込保護を残す。成功後に限り保護を解除する。明示的な保存ONで抑止を解除する際、保存先へ再導入されたファイルも再検証する。

Managerは削除時のWorldの既知発見を当回のmergeから除外し、後から新たに発見したIDは受け入れる。World自体を初期化しない。設定削除は現在の活動取得をOFFにして初回説明状態へ戻し、発見保存の選択を保持する。どちらも削除した種類の保存はOFF。GUIは確認の既定をキャンセルとし、成功と失敗を対象別に表示して設定画面を更新する。

単純なunlink、一覧clear、自動初期値上書き、フォルダ丸ごとの削除、Worldの強制終了は採用しない。別プロセスとの排他、診断ログ/キャッシュの所有と消去は別契約とする。これらを含む仕様31.7全体の完了を本変更だけで宣言しない。
