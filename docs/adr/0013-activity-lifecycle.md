# ADR 0013: 活動取得の実効休止をRuntimeで統合する

日付: 2026-09-12。状態: 採用。対象: v0.9.11。

活動OFF・手動一時停止ではProviderのpollだけを止めていた。WindowsのRaw InputコールバックはQtのイベント配送でも呼ばれるため、それだけでは入力解析とキューへの追加を止められない。また、OSロック解除がProviderを再開させ、活動OFFのまま取得処理が動く経路があった。

実効取得休止を「終了済み、手動一時停止、活動OFF、OS休止のいずれか」とする。Runtimeのすべての操作経路で同期し、最後の理由が解消したときだけ再開する。境界では集約済み入力、最後の活動フレーム、Provider内の入力キューを破棄する。既存のWindows休止機構を使用し、新たな入力APIや登録窓の再生成を導入しない。

Deferred Providerは未生成でも休止を保持する。休止中のpollは実取得元を生成せず、解除後の最初のpollで一度だけ生成する。取得元を差し替える際もRuntimeの状態を渡す。任意のテスト用Providerとの互換性のため、set_suspendedは既存どおり任意の拡張とする。

Worldの停止とは区別する。活動OFFだけならWorldは進行し、手動一時停止またはOS休止なら停止する。非表示だけでは取得状態を変更しない。終了後に解除通知が来ても取得を再開しない。

生の入力内容や他アプリケーションの情報を診断用に保存しない。保存形式、初回の説明と選択、LLM、描画素材は変更しない。
