# ADR 0009: 活動取得の初回選択と既存設定の継承

2026-09-09、v0.9.7。採用。

仕様31.2は初回説明と取得なし利用を求めるが、旧Settingsには説明状態がなく、GUI入口で実活動Providerを先に生成していた。ユーザーは既存ON/OFFを維持して説明を表示する方針を指定した。

Settingsのトップレベルに `activity_notice` を追加する。新規は `unseen`、旧JSONの項目欠落は `legacy`、新規選択後または旧説明を閉じた後は `shown` とする。未知の値は `unseen` として選択を求める。これは説明状態であり、同意履歴を表さない。schema_versionは1を維持し、旧版が無視できるトップレベルに限定する。旧版で再保存すると追加項目が落ち、戻した後に説明が再表示される場合がある。

新規の実活動GUIでは、選択を終えるまでProviderを生成しない。拒否時もWorldは動かし、既存の設定・トレイ操作で後から取得を再開できる。終了・閉じる・Escapeでは保存やWorldのタイマーも開始しない。選択と説明状態は一回の設定更新で保存する。

旧設定はON/OFF・その他の設定・発見を継承し、非モーダルの説明を表示する。閉じる操作は説明状態だけを更新する。クリック透過を使う環境のため、トレイからも説明を閉じられる。取得元は最初のpollで生成し、初期描画のstatus参照では生成しない。旧OFFも同じ境界を使う。

明示 `demo` / `none` と開発用途の注入済みProviderでは選択を省略し、説明済みにはしない。`--no-ui` は既存の非対話CLIを維持する。`--ephemeral` は既存設定を参照せず、選択・説明状態もメモリだけに置く。

全Providerのネイティブ取得停止・再開ライフサイクル、入力分類、一般的な破損JSON復旧は今回の対象外。既に生成された取得元の停止動作は従来どおりであり、この変更は初回の生成境界を保証する。

検証: [活動取得の説明](../activity-notice-verification.md)。OODA正本はv0.9.6 Decide/Act loop 002。
