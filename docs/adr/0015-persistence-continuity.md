# ADR 0015: ファイル別の書込み回復と累積発見の表示

日付: 2026-09-15 / 採用: v0.9.13

設定の置換失敗がWorldの更新処理から例外で抜け、正常な発見の保存まで止めていた。JsonStoreで書込みOSErrorを隔離し、読込み保護と独立した状態で扱う。

ファイル別に最新の未保存データをメモリで保持する。単調時計で5秒以上の間隔を設け、通常更新または休止中のタイマー、終了時の一度の最終試行で保存する。保存OFFの明示選択自体は既存どおり設定へ保存する。発見保存OFFは未保存発見の再試行を取り消す。ephemeralではStoreを作らない。

一時ファイルは当該Storeが生成したパスを再利用し、失敗のたびに増やさない。完全な書込みとクローズ後に原子的置換を行う。失敗した一時ファイルには不完全なデータが含まれる場合があり、次起動で正本として採用しない。取消時は所有する一時ファイルだけ削除を試し、削除できなければ再利用用に保持する。

画面は保存対象と未保存/再試行を固定文で表示し、成功で解除する。CLIの初回障害通知も固定文で、OS例外の内容を含めない。読込み保護のファイルは回復試行の対象外であり、再起動まで保護する。

発見タブだけをDiscoveryManagerの累積集合へ接続する。WorldSnapshotとWorldの発見は当回分を維持し、過去の発見で新規反応を誘発しない。保存不能時でも当回のメモリ内の発見を表示する。

無制限の毎フレーム再試行、全保存停止、自動初期化、Worldへの過去発見の注入は不採用。OSのI/O待ち時間上限と複数プロセス間調停は別課題。
