# 活動と時間の扱い

「設定 → 活動 → 集約間隔ms」で、活動をまとめる期間を100〜5000msの範囲で選べます。短い期間では早く活動が表示され、長い期間ではまとめて反映されます。設定変更は次の表示更新から更新間隔へ反映します。

ラボのWorldは1秒刻みで進みます。画面のアニメーションは別の周期です。更新を100msにしてもWorldが10倍速く進んだり、入力が10倍に増えたりしません。

| 集約期間 | Worldへの反映 |
|---|---|
| 100〜500ms | 複数の窓を期間で平均して1秒分にまとめる |
| 1000ms | 1窓を1回のWorld更新へ使う |
| 1000msを超える期間 | 閉じた窓を期間分だけ数回のWorld更新へ分配する |

長い窓は閉じるまで待ち、その後も何回かに分けて反映するため遅れが増えます。一度使った期間を繰り返し追加することはありません。種類や集約間隔の変更、活動OFF、一時停止、PC休止では未反映の活動を破棄し、復帰時にまとめて取り戻しません。

活動の種類別選択、反映量0〜1、保存保護と再試行は維持します。短時間で終了しても通常の設定・発見保存を試みます。1秒に満たない起動ではWorldがまだ更新されていないことがあります。

## CLIと安定性検証

--tick-interval-msは更新間隔の上限です。集約間隔が短ければ内部の更新を短くします。--frames×--tick-interval-msによる実行時間の予算は維持します。時間を明示したい場合は--duration-secondsと--stability-logを使ってください。

安定性ログの各tickに実際のtick_interval_msを記録します。GUIで途中の設定を変えても、指定された経過予定時間を満たして終了します。OSの処理遅延が完全になくなる保証ではありません。

同じ版・設定・seed・時刻付きの抽象入力なら、更新の粒度を変えてもWorld・乱数状態・Grid配置が一致します。旧版の重複反映と時計の扱いを修正したため、旧版とまったく同じ結果になる保証はありません。

## 検証範囲

100/200/500/1000/1500/5000msの窓と複数のheartbeatを組み合わせ、同じ10秒の状態一致を検証します。単一イベントの消費、境界/未来/古すぎる入力、レート正規化、期間の上限、端数時間、休止境界、Demoの時刻列、GUI途中変更とCLIの実間隔、短時間保存を確認します。

公開前後にWindows配布exeで期間とWorld時間、設定操作、起動・休止・トレイ・保存回復を確認します。利用者の入力内容や画面を記録しません。確認付き削除、通知/音声、長時間/全倍率/性能などの全体完成条件は別途継続します。
