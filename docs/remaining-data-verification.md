# ログ・キャッシュ・すべてのデータの削除

「設定 → データ」で、設定・発見に加えて次の操作ができます。削除前に対象を確認し、「キャンセル」やEscでは変更しません。

| 操作 | 対象と結果 |
|---|---|
| ログを削除 | 管理一覧にある診断ログを停止して削除する。別の起動で出力したログも対象 |
| 過去のログを選んで削除 | 以前の版などで作成した未登録ログを自分で選択する |
| キャッシュを削除 | アプリ内の画像・動作のキャッシュを読み直す。元画像とラボの状態は保持する |
| すべてのアプリデータを削除 | 設定・発見・対象ログ・管理一覧・保存用一時ファイル・キャッシュをまとめて扱う |

ログと全データの確認画面では「過去ログを追加」から未登録のログを加えられます。確認画面に対象を表示し、件数が多ければ「対象の一覧」で全件を確認できます。所在が記録されていない過去の出力は自動探索しません。以前保存した任意の場所のログも、選択すれば対象にできます。

削除したログへの出力はその実行中には再開しません。設定・発見の削除後は、それぞれの保存と活動取得の扱いが[設定・発見の削除](data-deletion-verification.md)に従います。ラボは続き、手動停止やPC休止は保持します。キャッシュは必要な画像を再度読み込むため、表示しながらメモリ使用量をゼロにする操作ではありません。

## 管理する情報

新しい診断ログの先頭にはアプリ名とログ形式の番号を付けます。通常実行では、選択中の保存先のlog-index.jsonに、ログの絶対パスと先頭行のSHA256を記録します。入力内容やログ本文を一覧へ複製しません。設定・発見の形式は変わりません。ログを作らない通常起動では、空の管理一覧を新設しません。

削除直前に保存先と識別値を照合します。別の内容へ置き換えられたファイル、リンク、診断ログと確認できないファイルは消しません。未知のファイルや保存フォルダ全体、同梱素材の原本を再帰的に削除することもありません。

## 失敗と一時実行

使用中のログ、保存できない管理一覧、読み込めない管理一覧などは、未完了として表示します。成功した対象を戻すことはできませんが、残った対象は改めて削除できます。管理一覧が壊れている場合は原本を保護し、所在不明のログを含めてすべて消せたとは表示しません。元の一覧を復元して再起動するか、過去ログの選択から対象を指定してください。正常な設定・発見の保存は続きます。

一時実行（--ephemeral）では既存保存先や管理一覧を読み書きしません。永続データの削除と過去ログ選択は無効で、キャッシュ操作だけ使用できます。明示した--stability-logへの診断出力は従来どおり可能ですが、永続管理一覧へは登録しません。

複数のプロセスが同じ保存先やログを同時使用する排他制御は、別の未完了項目です。所在一覧は4096件までで、登録できない場合は通知します。上限超過のログや古い未登録ログはファイル選択から扱えます。
